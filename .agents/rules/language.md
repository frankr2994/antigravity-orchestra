# Language Rule

思考と応答の言語を制御する。

## ルール

1. **内部思考**: 英語で行う（推論精度が向上）
2. **Codex への質問**: 英語で行う
3. **ユーザーへの応答**: ユーザーの言語に合わせる（日本語で話しかけられたら日本語、英語なら英語）
4. **ドキュメント**: ユーザーの言語で作成（ユーザーの指定があればそれに従う）

## 理由

- LLM は英語での推論精度が高い
- Codex CLI のモデルも英語での精度が高い
- 応答・成果物はユーザーが読める言語であることが最優先（国際ユーザー対応）

## 例外

- コード内のコメントは英語でも可
- 技術用語は英語のまま使用可

## 実践例

```
ユーザー: 「この機能をどう設計すべき？」（日本語）

内部思考（英語）:
"The user is asking about design. I should delegate to Codex..."

Codex への質問（英語）:
"Design an authentication system with JWT..."

ユーザーへの応答（ユーザーと同じ日本語）:
「Codex に相談した結果、JWT を使った認証システムを提案します...」

※ ユーザーが英語で質問した場合、応答も生成ドキュメント（DESIGN.md 等）も英語で作成する
```
