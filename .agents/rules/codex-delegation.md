# Codex Delegation Rule

Codex CLI への委譲に関するルール。

## 基本原則

Codex CLI は「深い推論が必要なタスク」を担当する。

## Codex に委譲するタスク

| タスク | 理由 |
|--------|------|
| アーキテクチャ設計 | 複数の選択肢を比較検討する必要がある |
| テスト設計（TDD） | テストケースの網羅性を考慮する必要がある |
| デバッグ | 根本原因の分析が必要 |
| コードレビュー | 客観的な視点で品質を評価する必要がある |
| トレードオフ分析 | 複数の観点からの比較が必要 |

## Codex に委譲しないタスク

| タスク | 理由 |
|--------|------|
| ファイル編集 | Antigravity が直接行う |
| リサーチ | Antigravity 自身が 1M トークンを活用 |
| ユーザーとの会話 | Antigravity が担当 |
| 単純なコード生成 | Codex の深い推論は不要 |

## 委譲時のプロトコル

1. **コンテキストを渡す**: 関連ファイル、背景情報、原要求、担当フェーズ、受け入れ条件、既存の未解決指摘
2. **質問を明確に**: 何を判断してほしいか
3. **出力形式を指定**: 構造化された回答と、各指摘が後続作業をブロックするかの判断を要求
4. **結果を記録**: `logs/codex-responses/` に保存

## レビューゲート

- 外部契約、前提アーキテクチャ、またはセキュリティ、ID、耐久性、Git、永続化、
  並行処理、復旧、未信頼コード実行の安全性を無効化する確認済み指摘は、依存する
  実装をブロックする
- ブロッカーは修復して再レビューで確認するまで、後続の依存フェーズへ進まない
- 最終修復パスの予定は、基礎的ブロッカーを先送りする理由にならない
- 非ブロッキング指摘を延期する場合は、理由、影響、再確認条件を記録する
- テストが実装側で発明した契約だけを検証していると判明した場合、後続コードがその
  テストへ依存する前に、実運用契約を検証するテストへ置換する

## 委譲の例

```
良い委譲:
「このコードのセキュリティ脆弱性を分析して」
「この2つのアプローチのトレードオフを比較して」

悪い委譲:
「このファイルを編集して」（→ Antigravity が直接行う）
「このライブラリについて調べて」（→ Antigravity が行う）
```
